# Supported IDEs & Compatibility Guide

TaintFlow+ is built on a modular architecture that separates the core security verification engine from the visual interfaces. By exposing a Model Context Protocol (MCP) server, it seamlessly synchronizes code scan diagnostics and workspace intelligence across multiple modern IDEs.

---

## Compatibility Table

| IDE / Client | Supported Version | Connection Mode | Support Level |
| :--- | :--- | :--- | :--- |
| **VS Code** | `v1.85.0` or higher | Full Extension + Workspace MCP | **Full** (UI, Diagnostics, Webviews) |
| **Cursor** | `v0.40` or higher | Workspace & Global MCP Server | **Excellent** (MCP Tools, Diagnostics) |
| **Antigravity** | `v1.0` or higher | Antigravity-Skill Integration | **Full** (MCP Tools, Native Agent Skill) |
| **Windsurf** | Latest | Codeium MCP config path | **Experimental** (Standard Stdio MCP) |

---

## Supported Features by IDE

### 1. VS Code
- **Real-Time Editor Warnings**: Uses VS Code Diagnostics to underline security vulnerabilities inline.
- **Tree-View Dashboard**: Tree provider in the activity sidebar summarizing vulnerabilities sorted by severity.
- **Graphify Interactive Webview**: Renders a dynamic node graph mapping repository relationships and flows in a split editor tab or full-screen view.
- **Secure Key Storage**: Integrates with the OS Keychain using VS Code's `ExtensionContext.secrets` API.
- **Quick Fixes**: Inline commands via `codeActionsProvider` to automatically refactor vulnerable code.

### 2. Cursor
- **Tool Calls**: AI Agent in Cursor can run the `verify_code` tool of the TaintFlow+ MCP server synchronously.
- **Context Awareness**: TaintFlow+ scans files passed inside agent chats.
- **Diagnostics**: Custom MCP warnings synchronize to the active editor workspace.

### 3. Antigravity (Google Gemini IDE)
- **Native Skill Registry**: Registers as an autonomous workspace skill (`antigravity-skill/skill.json`) that the Gemini agent can invoke automatically during coding tasks.
- **Taint Verification**: Verifies generated code outputs for taint flows prior to presenting them to the user.

## Known Limitations

- **Ollama Performance on Low-Resource Systems**: When running in `local` mode, Ollama is dependent on your host hardware. Systems with less than 8GB RAM may experience analysis latency when querying large chunks of code.
- **MCP Server Stdio Locks**: In some environments, if multiple IDEs run at the same time pointing to the same global MCP server bundle, the stdio sockets can occasionally lock. It is recommended to use the workspace-level `mcp.json` settings generated by `npm run setup-mcp`.
- **Sandbox Restrictions**: Webviews loaded inside VS Code are sandboxed. They require standard security policies to communicate with the extension process, which may block inline frames (iframes) referencing external scripts.

## Compatibility Notes

### Configuration Synchronization
When you run:
```bash
npm run setup-mcp
```
The script reads your `.env` configuration file and automatically synchronizes the server endpoints and credentials to the following locations:
- **VS Code**: Writes to `.vscode/mcp.json`
- **Cursor**: Writes to `.cursor/mcp.json` (project-specific) and your global system config directory.
- **Antigravity**: Writes to `~/.gemini/antigravity/mcp_config.json`.
- **Windsurf**: Writes to `~/.codeium/windsurf/mcp_config.json`.

This ensures that the exact same analysis engine handles code verification regardless of which editor window you open.
